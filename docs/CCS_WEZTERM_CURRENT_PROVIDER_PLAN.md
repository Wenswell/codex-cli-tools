# ccs WezTerm current provider plan

## Goal

Show the active switching profile in the compact `ccs` status with a leading `*`, including the WezTerm right status generated by `ccs s agent`.

```text
12:34:56 r18s | aaa 123.5 | *bbb 321.5
```

## Design

- Use `profiles.current` as the single source of active-profile state.
- Add the marker while rendering each compact status entry.
- Share the same rendering rule across `ccs s`, `ccs s line`, and the WezTerm status cache.
- Reload `profiles.json` on each status-agent refresh so profile switches appear without restarting the agent.
- Write `profiles.json` atomically so concurrent status reads always observe a complete document.
- Validate that `profiles.current` belongs to `profiles` before applying the marker, keeping usage-only entries outside the switching profile set.
- Preserve the existing snapshot and cache-file schemas; the marker is display data.

## Acceptance Criteria

- The entry whose name equals `profiles.current` starts with `*`.
- Other entries retain their configured names and order.
- A missing or unmatched `profiles.current` produces no marker.
- README examples and WezTerm guidance describe the marker.
- Focused CLI tests, the TypeScript check, and the full test suite pass.

## Result

- Compact status rendering marks the entry matching the latest `profiles.current` value.
- The status agent reloads the profile configuration on each refresh, so WezTerm reflects profile switches without a restart.
- Profile configuration writes are atomic, keeping concurrent readers on complete JSON documents.
- Tests cover a non-first current entry, an unmatched current value, and a running agent observing a real `ccs toggle` profile switch.
- `pnpm check` and all 114 tests pass.
